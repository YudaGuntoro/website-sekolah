# Cendekia Dashboard project notes

- This checkout is Cendekia's school CMS. It has no Dental Care Git remote.
- Frontend: `Frontend` (port 3002); API: `Backend/DentalCare.WebAPI` (port 5243).
- Local database bootstrap is `database/cendekia_cms.sql`, followed by `database/seed_cendekia_content.sql`.
- SPMB schema is `database/spmb.sql`. For existing installations run `scripts/init-local-db.ps1 -SpmbOnly` without reseeding website content.
- SPMB has exactly four date-based waves, uses WIB (Asia/Jakarta), closes outside active dates, and keeps the wave/year snapshot on each application.
- SPMB information uses typed singleton `spmb_information` (upgrade `scripts/init-local-db.ps1 -SpmbInformationOnly`) and `/spmb/informasi` admin editor. Public `/spmb` retains its timeline, fee panel, document lists, and contact footer. Year comes from the wave schedule, contacts from website_settings. `/content/spmb` redirects to the typed editor; older `school_content` spmb records are retained as archive and no longer render this page. Built-in step icon keys: register/folder/payment/test/check/book. Do not restore generic ContentSections for this page.
- Use only the `cendekia_cms` database. Legacy clinic SQL and deployment docs are retained template references, not school setup instructions.
- This repository includes the website at `../package` relative to this dashboard folder. `SCHOOL_API_URL` connects it to this API. Commit and push from the repository root; this folder is ordinary source, not a submodule or separate repository.
- Instagram/TikTok feeds use CMS collections `instagram` and `tiktok` with a dedicated `PostUrl` field. Upgrade existing databases with `scripts/init-local-db.ps1 -SocialOnly`; do not reseed existing content. Only HTTPS post URLs from the matching platform are accepted.
- Website contacts use the singleton `website_settings` table. Upgrade with `scripts/init-local-db.ps1 -WebsiteSettingsOnly`. ADMIN/SUPERVISOR may edit; the public `/api/school/contact` endpoint supplies footer, homepage contacts, and WhatsApp bubble. Blank fields stay hidden instead of falling back to old values.
- Principal greeting uses collection `sambutan`: Title is the principal name, Category is the role, Body contains all greeting paragraphs, ImageUrl is the portrait. Only the latest published entry appears in the homepage. Initialize existing installations once with `scripts/init-local-db.ps1 -PrincipalOnly`; the seed preserves any existing greeting including drafts.
- Vision, motto, and ordered mission points use singleton `school_identity`; upgrade with `scripts/init-local-db.ps1 -IdentityOnly`. Admin UI is `/settings/identity` under Profil Sekolah. CMS editor roles can save with optimistic versioning. Public `/api/school/identity` supplies desktop vision/motto/missions and mobile mission titles/content. Do not revert to hardcoded values for blank fields.
- Three homepage illustration overrides use `homepage_images`; upgrade with `scripts/init-local-db.ps1 -ImagesOnly`. Admin UI `/settings/images`, API `/api/cms/homepage-images`, public `/api/school/homepage-images`. Empty URLs and failed image loads use the original assets for hero, Arah Pendidikan, and Program Belajar. Overrides do not change per-program card images.
- Only school CMS, SPMB, authentication, and user controllers are enabled. Do not re-enable clinic routes.
- LMP means Lomba Mata Pelajaran, separate from SPMB. Public `/lmp` and `/lmp/daftar`, admin `/lmp/informasi` and `/lmp/pendaftar`, API `/api/lmp`. Initialize existing installations with `scripts/init-local-db.ps1 -LmpOnly`. Singleton `lmp_settings` uses optimistic versioning; registration closes outside inclusive WIB dates. Each class 5–6 SD participant selects exactly one of Matematika/Bahasa Indonesia/Bahasa Inggris. Private PDF files (max 2 MB) are stored in `lmp_applications.Document` and downloaded only through staff-authenticated endpoints, never public static URLs. Application list sorts newest Id first. Submission stores event date/title/fee snapshots, independent payment and registration statuses; no automatic payment verification. Defaults: competition 21 January 2027 07.30–16.00 WIB; announcements/gebyar 28 January 2027. Unconfirmed registration dates, document requirements, bank account and WhatsApp group remain unset/pending.
- Keep browser API calls same-origin under `/api`; local Next.js forwarding uses `API_PROXY_TARGET`.
- Keep production database credentials and signing keys in the server environment file; never commit or print them.
